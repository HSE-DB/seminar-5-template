# Семинар 5: SQL-запросы к библиотечной системе и расписанию поездов

Напишите семь запросов на PostgreSQL к двум готовым базам данных. Схемы и учебные данные находятся в `docker/sql/`, ответы — в [src/answers.md](src/answers.md).

## Начало работы

1. Клонируйте свой репозиторий из GitHub Classroom и создайте ветку:

   ```bash
   git switch -c seminar-5-solution
   ```

2. Запустите базы из корня репозитория. Нужен работающий Docker с Compose:

   ```bash
   docker compose -f docker/docker-compose.yml up -d --wait
   ```

3. Подключитесь из DataGrip или другого SQL-клиента:

   | База | Адрес | Порт | Пользователь | Пароль |
   | --- | --- | ---: | --- | --- |
   | `library` | `localhost` | 5444 | `library` | `library` |
   | `train` | `localhost` | 5445 | `train` | `train` |

4. Запишите каждый ответ в соответствующий блок `sql` в `src/answers.md`. Сохраните заголовки частей и вопросов. В каждом блоке должен быть один запрос `SELECT` или `WITH ... SELECT`, без изменения данных. Завершающая точка с запятой необязательна.

Все результаты должны содержать **уникальные строки** и столбцы **в указанном порядке**. Порядок строк и названия псевдонимов столбцов произвольные. Тесты проверяют результат запроса, поэтому можно использовать разные способы соединения таблиц, подзапросы и CTE.

## Часть 1: Библиотечная система

Используйте реальные имена из [docker/sql/library/init.sql](docker/sql/library/init.sql):

- `Reader (ID, LastName, FirstName, Address, BirthDate)`
- `Publisher (PubName, PubKind, Address)`
- `Book (ISBN, Title, Author, Number_of_pages, Year, Publisher_Name)`
- `Category (CategoryName, ParentCat)`
- `Copy (ISBN, CopyNumber, Position)`
- `BookCategory (ISBN, CategoryName)`
- `Borrowing (ID, ISBN, CopyNumber, ReturnDate)`

`Borrowing.ID` ссылается на читателя. Экземпляр определяется парой `(ISBN, CopyNumber)`. `ReturnDate IS NULL` означает, что экземпляр ещё не возвращён; заполненная дата — факт возврата. Адрес начинается с названия города, за которым могут идти запятая и улица. В данных ровно один читатель с именем Иван Иванов; его ID заранее неизвестен.

1. Найдите фамилии читателей, проживающих в Москве. Результат: `LastName`.
2. Найдите книги, которые брал Иван Иванов, независимо от возврата. Разные экземпляры одной книги не должны давать повторы. Результат: `Author, Title`.
3. Найдите ISBN книг, непосредственно относящихся к категории «Горы», но не относящихся непосредственно к категории «Путешествия». Подкатегории обеих категорий игнорируйте. У книги могут быть и другие категории. Результат: `ISBN`.
4. Найдите читателей, вернувших хотя бы один экземпляр книги. Результат: `LastName, FirstName`.
5. Найдите читателей, которые брали хотя бы одну из тех же книг, что и Иван Иванов. Номера экземпляров могут различаться; возврат не важен. Исключите самого Ивана Иванова, но сохраните других читателей с таким же именем или фамилией. Результат: `LastName, FirstName`.

## Часть 2: Поезда

Схема находится в [docker/sql/train/init.sql](docker/sql/train/init.sql):

- `City (Name, Region)`
- `Station (Name, Tracks, CityName, Region)`
- `Train (TrainNr, Length, StartStationName, EndStationName)`
- `Connection (FromStation, ToStation, TrainNr, Departure, Arrival)`

`FromStation` и `ToStation` содержат названия **станций**. Город определяется по `Station.CityName`; у города составной ключ `(Name, Region)`. В одном городе может быть несколько станций.

Считайте, что `Connection` содержит транзитивное замыкание участков одного поезда: для поездки A → B → C могут существовать записи A → B, B → C и A → C. Поэтому одна запись означает поездку без смены поезда, даже если есть промежуточные остановки.

1. Найдите все прямые рейсы из Москвы в Тверь. Учитывайте все станции обоих городов, а также разные отправления одного поезда. Результат: `FromStation, ToStation, TrainNr, Departure, Arrival`.
2. Найдите все маршруты из Москвы в Санкт-Петербург **ровно с одной пересадкой на другой поезд**:
   - прибытие первого поезда и отправление второго происходят на одной станции;
   - второй поезд отправляется не раньше прибытия первого; равенство времени допускается;
   - первое отправление и конечное прибытие приходятся на одну календарную дату, включая месяц и год.

   Результат: `FirstTrainNr, SecondTrainNr, TransferStation, Departure, Arrival`, где последние два столбца — первое отправление и конечное прибытие. Это порядок значений; псевдонимы можно выбрать самостоятельно.

В PostgreSQL сравнивайте полные даты, например через приведение `timestamp` к `date`. Сравнения только номеров дней недостаточно. Справочник: [функции даты и времени PostgreSQL](https://www.postgresql.org/docs/18/functions-datetime.html).

## Автопроверка

GitHub Classroom запускает проверки при отправке изменений и открытии PR. Максимум — **10 баллов**:

| Проверка | Баллы |
| --- | ---: |
| Библиотека 1: читатели из Москвы | 1 |
| Библиотека 2: книги Ивана Иванова | 1 |
| Библиотека 3: категории книг | 2 |
| Библиотека 4: возвраты | 1 |
| Библиотека 5: общие книги | 2 |
| Поезда 1: прямые рейсы | 1 |
| Поезда 2: маршруты с пересадкой | 2 |

Для локальной проверки нужны Python 3.10+ и Docker. Дополнительные Python-пакеты не требуются. Запускайте из корня репозитория:

```bash
python3 .tests/test_sql_helpers.py
python3 .tests/test_sql_runtime.py
python3 .tests/test_sql_answers.py
```

Можно проверить один вопрос:

```bash
python3 .tests/test_sql_answers.py SqlAnswersTests.test_train_2
```

Тесты создают отдельный временный контейнер PostgreSQL 18, загружают схемы и проверяют запросы на нескольких наборах данных, включая пустые таблицы. ID, ISBN, названия станций и номера поездов меняются. Учитываются повторы, `NULL`, дополнительные категории, разные экземпляры книг, несовпадающие станции пересадки, невозможные стыковки и одинаковые номера дней в разных месяцах и годах. Запросы выполняются с правами на чтение и ограничением времени. После проверки временный контейнер и его данные удаляются.

Учебные данные для DataGrip фиксированы и загружаются при первом запуске контейнеров. Если база уже создана со старым набором данных, для её пересоздания выполните `docker compose -f docker/docker-compose.yml down -v`, а затем снова `up -d --wait`. Команда `down -v` удалит данные учебных баз этого Compose-проекта.

Пустой шаблон ответов должен проваливать проверки заданий. Тесты вспомогательных функций отдельно проверяют сам механизм оценивания и не приносят баллов.
